HOUSEKEEPING - SWEEP EDITOR ARTIFACTS (do this whenever opening a file after CloudCannon use)
CloudCannon saves leave empty <p></p> tags and stray <p> wrappers around <div> blocks. They
are invisible in the editor but add real vertical space, and stacked ones (six at the end of
Day 2 on Aug 4) look like a layout bug. Sweep:
  - Remove all empty paragraphs:  re.subn(r'[ \t]*<p>\s*</p>\n?', '', src)   -> safe
  - Unwrap stray <p> that only wraps a <div>: handle each instance EXPLICITLY by exact string.
  - VALIDATE after every step and re-verify content counts (videos 8, tri.ps 6, coach cards 2,

  - DO NOT use a broad regex for orphan </p> tags. Tried twice, broke the HTML both times,
    had to restore itinerary27.html from GitHub. Restoring from GitHub is the safety net -
    use it the moment the validator reports unclosed tags.

CLOUDCANNON GOTCHA - STRAY TAGS ON SAVE (learned Aug 3)
CloudCannon's rich-text editor "tidies" hand-built HTML when it saves. It injects stray <p>
wrappers and converts <br> to <br />, &bull; to a literal bullet, etc. Ordinary paragraph
sections absorb this harmlessly, but it BREAKS CSS grid/flex blocks, because a stray tag
becomes an extra grid child.
  - Seen on: the .coach cards (a stray <p> between the photo and the text div pushed the bio
    into the narrow photo column) and a doubled "|" separator in the footer legal line.
  - After any CloudCannon save, check grid-based blocks: .coach cards, .price-card,
    .vid-grid, .staff cards, the hero.
  - Fix: remove the injected <p> and its orphan </p> INSIDE that one block only. Do not run a
    broad regex over the whole file - a greedy pattern stripped legitimate closing tags and
    had to be reverted from GitHub.

MERGE RECOVERY - IF CLOUDCANNON AND CLAUDE EDIT THE SAME FILE (procedure proven Aug 3)
Symptom: CloudCannon shows "syncing is paused" then Pull/Push fail; Syncs tab shows
"CONFLICT (content): Merge conflict in <file>". Nothing is lost - both versions still exist.
  1. Have Bob SAVE in CloudCannon (do not discard). His edits live only in that session.
  2. Snapshot GitHub's current version of the file (that is Claude's side).
  3. In CloudCannon click Rebuild, then fetch the file from the testing domain
     (salmon-iris.cloudvent.net/<page>.html) - that serves CloudCannon's copy = Bob's version.
     Verify it is clean (no injected cloudcannon/cloudvent markers).
  4. Fetch the common ancestor: the commit on that file BEFORE Claude's change, via
     api.github.com/repos/capecodbob421/sporteurotour-site/commits?path=<file>
     then raw.githubusercontent.com/.../<sha>/<file>.
  5. Three-way merge: git merge-file -p mine.html base.html theirs.html > merged.html
     Resolve conflicts by hand (Aug 3 had one, in the hero - kept Claude's version because
     CloudCannon's side was only stale markup, not a real edit).
  6. Verify BOTH sets of edits survive with explicit string counts before publishing.
  7. Publish merged file to GitHub.
  8. In CloudCannon: Site Settings > Syncing > "Reset using Git repository main"
     (confirm "Clear and reconnect"). Safe once the merge is on GitHub; CloudCannon also
     keeps a backup under Site Settings > Backups.
  9. Confirm Pull and Build show Completed and the testing domain matches the live site.
PREVENTION: never have CloudCannon open on the same page Claude is working on. One editor per
page at a time.

SYNCING PAUSED - NO CONFLICT, JUST AN UNSAVED FILE (fastest fix, proven Aug 5)
Symptom: Dashboard Pull fails with "Remote changes would overwrite files that are open in the
editor. Please save your changes and try again." This is NOT a merge conflict. It means
CloudCannon is holding unsaved edits on a file that GitHub has also changed.
THE FIX (30 seconds, do this FIRST before any merge recovery):
  1. Click the SAVE button, top right of CloudCannon. It opens the "Save changes" panel and
     does NOT save anything by itself.
  2. The panel lists every file with unsaved edits, each with a checkbox.
  3. Confirm the GitHub copy is the one to keep (curl the raw file and compare), then click
     "Discard selected" > "Discard unsaved changes".
  4. Syncing resumes on its own. Pull and Build run automatically within seconds.
  5. Verify: the blue "Edited" badge is gone from the Pages collection and the new file
     (e.g. teams.html) now appears in the list.
NOTE: "Discard unsaved changes" from inside the page editor's three-dot menu does NOT clear it.
The Save panel is the only place that works. Also: "Reset using Git repository main" does not
clear it either - the unsaved file survives the reset.
DO NOT click "Save all" in that panel unless Bob's CloudCannon edits are wanted. Save all
overwrites GitHub with CloudCannon's copy.

5. Cutover: point DNS at GoDaddy to the Cloudflare site (custom domain sporteurotour.com added in Cloudflare first). Rollback = point DNS back to WP Engine.
6. Keep WP Engine active about a month after cutover, confirm nothing breaks, then cancel.
